这篇文章只做一件事：把两个容易被分开讨论的方向放进同一张系统图里。第一个方向是具身智能安全，重点是智能系统通过传感器接触外部世界，再通过执行器改变外部世界。第二个方向是抗量子密码，重点是今天依赖 RSA、ECC 等公钥算法的通信、身份和签名体系，未来要迁移到能抵抗量子计算攻击的方案。

这是一篇有限导读，只覆盖概念、资料和最小练习。目标是建立基本概念、知道该读哪些可靠资料、看懂一些研究问题为什么重要。真正深入时，具身智能会走向机器人学、控制、感知、仿真和安全评测；抗量子密码会走向密码学、协议工程、证书体系、迁移治理和软硬件实现。这里先把地图画清楚。

## 学完要能做什么

读完以后，应该能够回答这些问题：

1. 具身智能为什么要从传感器、坐标、状态估计和执行器讲起。
2. 大语言模型、视觉语言动作模型和机器人控制栈分别处在什么层次。
3. 抗量子密码解决的是哪类密码威胁，为什么它和网络安全、设备安全、软件供应链有关。
4. 为什么 NIST 的 PQC 标准不等于“所有系统已经自动安全”。
5. 一个真实机器人、车、无人机、工业臂或边缘设备里，哪些位置会同时遇到物理安全、模型安全和密码迁移问题。
6. 初学者可以按什么顺序补基础，避免被论文名词带着走。

## 先把问题放到同一个系统里

网络安全经常从资产、信任边界和攻击面开始分析。具身智能和抗量子密码也可以用同一套问题框架理解：

| 问题 | 在具身智能里怎么出现 | 在抗量子密码里怎么出现 |
| --- | --- | --- |
| 资产是什么 | 人身安全、设备、任务数据、地图、模型、日志、控制权限 | 长期保密数据、会话密钥、证书、签名、固件、供应链证据 |
| 信任边界在哪里 | 传感器输入、坐标变换、规划策略、控制器、执行器、远程运维接口 | TLS/SSH/VPN、PKI、密钥交换、签名验证、HSM、证书生命周期 |
| 失败会造成什么 | 撞击、误抓取、越界移动、错判障碍、任务中断 | 历史密文被将来解密、身份伪造、固件被替换、日志证据失效 |
| 为什么现在要准备 | 真实世界反馈快，测试覆盖难，仿真和现实有差距 | 迁移周期长，硬件和协议迭代慢，长期保密数据有“先收集后解密”风险 |

安全问题一旦接触真实系统，就很少只停在单个算法。一个移动机器人可能通过 Wi-Fi 或 5G 接入云端，下载模型或地图，使用证书验证 OTA 固件，通过相机和 LiDAR 感知外部世界，再把规划结果发给电机控制器。攻击面横跨网络、软件供应链、传感器、模型、控制和物理空间。

## 具身智能：机制从传感器到动作闭环开始

具身智能的核心在于：系统在外部世界中感知、决策、行动，并承受行动后果。一个最小闭环可以写成：

```text
外部世界
  -> 传感器
  -> 时间同步与坐标系
  -> 感知与状态估计
  -> 世界模型
  -> 任务规划与动作策略
  -> 控制器与执行器
  -> 外部世界发生变化
```

这个闭环里，每一层都有自己的错误模式。

### 传感器层：数据来自物理世界

常见传感器包括 RGB 相机、深度相机、LiDAR、IMU、轮速计、关节编码器、力矩传感器和触觉传感器。传感器比“输入张量”多出物理属性。它们有采样频率、延迟、噪声、遮挡、标定误差、温度漂移和安装位置。

一个相机检测到障碍物，只说明某个时刻、某个视角下的像素支持这个判断。机器人要移动时，还要知道障碍物在机器人坐标系里的位置，障碍物是否在运动，检测结果是否过期，控制器接下来会怎样改变距离。

### 坐标和时间层：很多错误来自“对不上”

机器人系统通常同时存在多个坐标系：世界坐标、地图坐标、机器人底盘坐标、相机坐标、机械臂末端坐标。Nav2 文档把 transform 作为导航 setup 的基础主题，就是因为定位、地图、传感器和规划只有在坐标关系正确时才能组合。

一个简化例子：

```text
camera_frame 中的障碍点:  (x=0.3, y=0.1, z=1.2)
base_link 中的障碍点:     需要通过相机外参转换
map 中的障碍点:           还需要机器人当前定位
planner 使用的障碍点:      还要考虑时间戳和地图更新
```

如果坐标变换错了，模型输出再漂亮也可能让机器人朝错误方向避障。如果时间戳错了，系统可能用过期位置规划下一步动作。

### 状态估计和世界模型层：系统要维护“我在哪里、世界怎样”

状态估计会融合多个来源：轮速计短时间平滑但会累计漂移，IMU 响应快但噪声大，视觉或 LiDAR 可以帮助定位但会受环境影响。SLAM、滤波、地图更新和语义理解都属于这一层。

世界模型即使很朴素，也有价值。对一个仓库机器人来说，世界模型可以只是局部 costmap、障碍物列表、通行区域和目标点；对一个家庭机器人来说，世界模型可能包括房间、物体、可抓取位置、人类位置和任务状态。

### 规划、策略和控制层：高层意图要变成可执行动作

规划回答“要走哪条路、抓哪个物体、下一步做什么”。控制回答“电机如何运动、力矩如何限制、速度如何平滑”。视觉语言动作模型可以把图像和文字指令映射到动作策略，但它仍然需要传感器、坐标、状态估计、控制器和安全监控配合。

一个简单的安全监控规则可能是：

```text
IF 人体距离机械臂末端 < 安全距离
THEN 限速或停机

IF 规划轨迹穿过禁入区域
THEN 拒绝执行并要求重新规划

IF 传感器时间戳过旧
THEN 不允许使用该帧更新控制命令
```

这些规则看似朴素，却能暴露具身安全的关键点：真实系统需要运行时约束。只在离线评测里回答正确，不等于上线后行动安全。

## 为什么要引入具身智能安全

具身系统的风险比纯文本或纯图像系统更难处理，因为输出会改变环境。一次错误回答可以被人类忽略；一次错误动作可能损坏设备、撞到人、泄露空间信息或触发连锁故障。

安全分析至少要覆盖四类问题：

1. **传感器可信度**：遮挡、反光、对抗贴纸、光照变化、GPS 欺骗、LiDAR 干扰会不会改变感知。
2. **模型和策略边界**：训练数据没有覆盖的场景，策略是否会自信执行。
3. **运行时约束**：速度、力、空间边界、急停和人工接管是否独立于主策略存在。
4. **系统与供应链**：模型文件、固件、地图、远程命令和日志是否能被认证、审计和回滚。

NIST 的机器人测量项目强调，机器人是系统之系统，需要分别评估组件表现和整体表现，也需要用场景和指标表达性能需求。这一点对学习路线很有启发：研究具身智能安全时，不能只看一个模型 benchmark，要同时看传感器、数据、任务、环境、控制和验证方法。

## 抗量子密码：先分清它解决什么问题

抗量子密码通常指 post-quantum cryptography，缩写 PQC。它的目标是在普通计算机上运行新的公钥密码算法，使这些算法能够抵抗未来足够强的量子计算机攻击。它和量子密钥分发属于不同路线；PQC 更像是要替换或补充现有 TLS、SSH、VPN、PKI、代码签名、设备身份里的公钥算法。

需要先抓住两个量子算法的影响：

| 量子算法 | 影响的传统密码 | 直观含义 |
| --- | --- | --- |
| Shor 算法 | RSA、有限域 Diffie-Hellman、椭圆曲线密码 | 足够强的量子计算机可能破坏今天大量公钥密钥交换和签名机制 |
| Grover 算法 | 对称密钥搜索和哈希搜索的安全裕量 | 通常通过增加对称密钥和哈希长度来保留安全裕量 |

所以 PQC 的迁移重点是识别并替换量子脆弱的公钥算法。更实际的第一步是盘点这些算法出现在哪里：

```text
TLS 证书和握手
SSH 主机密钥和用户密钥
VPN / IPsec / WireGuard 周边认证材料
代码签名和固件签名
容器镜像签名、软件包签名、SBOM 证据链
设备出厂证书和长期身份
数据库备份、归档、日志的长期保密需求
```

NIST 在 2024 年发布了三项主要 PQC FIPS 标准：FIPS 203 是 ML-KEM，用于密钥封装；FIPS 204 是 ML-DSA，用于数字签名；FIPS 205 是 SLH-DSA，也是数字签名。NIST 的 PQC 项目页面还说明，组织应该开始应用这些标准并规划迁移；NIST/NCCoE 迁移资料把密码资产发现、风险优先级和互操作测试作为重要工作流。

## 为什么迁移会超过“换一个库”

密码算法通常藏在系统深处。一个公司可能知道自己用了 HTTPS，却不清楚每个服务、网关、设备、SDK、证书签发流程、固件更新工具、镜像仓库和第三方依赖分别用了哪些算法。迁移还会遇到这些工程问题：

1. **资产发现**：先知道哪里用了 RSA、ECDSA、ECDH、DH、证书链和签名格式。
2. **协议兼容**：客户端、服务端、中间件、硬件模块和审计工具是否支持新算法。
3. **证书生命周期**：证书申请、签发、轮换、吊销、日志和监控都要跟着改。
4. **性能与包大小**：PQC 密钥、签名和握手数据大小可能不同，嵌入式设备和网络协议要重新测试。
5. **密码敏捷性**：系统要能替换算法、并行试验、回滚和观测，避免把算法写死在业务代码里。

初学者可以先把 PQC 看成“安全迁移工程问题”。数学原理重要，但工程上首先要回答：资产在哪里、风险多大、谁依赖它、换了以后如何验证。

## 两条线在哪里交叉

具身智能系统通常连接远程运维、模型更新、地图同步、日志上传、设备身份、固件签名和供应链依赖。于是具身安全和抗量子迁移会在多个边界相遇：

| 交叉点 | 具身系统中的问题 | PQC 视角的问题 |
| --- | --- | --- |
| OTA 固件更新 | 更新包如果被替换，设备可能执行错误控制逻辑 | 固件签名需要长期可信，签名算法要能迁移 |
| 机器人到云端通信 | 地图、视频、遥测、任务命令需要认证和保密 | TLS/VPN/设备证书要盘点和迁移 |
| 模型和地图供应链 | 模型文件、地图、配置被污染会改变行为 | 包签名、镜像签名、证据链要考虑未来可验证性 |
| 现场日志 | 事故复盘依赖日志完整性和时间顺序 | 签名、时间戳和哈希策略要能长期审计 |
| 边缘设备寿命 | 工业机器人、车载设备、传感器可能服役多年 | 长生命周期设备更早需要密码敏捷性 |

这也是为什么学习具身智能安全不能只看模型论文，学习 PQC 不能只看算法表。真实系统会把模型、机器人、网络、密钥、证书、固件和运维流程绑在一起。

## 初学者怎么补基础

可以按五个阶段学习，每个阶段只抓关键问题。

### 第一阶段：网络和密码常识

先知道 TLS、证书、密钥交换、数字签名和哈希分别解决什么问题。目标是读懂一个服务为什么需要证书，为什么签名能证明固件没有被替换，为什么长期保密数据要提前考虑未来威胁。

可以做一个只读观察练习：

```bash
openssl version
openssl ciphers -v | head
ssh -Q key | head
ssh -Q kex | head
```

预期观察：可看到本机 OpenSSL 和 SSH 支持的密码套件、主机密钥类型和密钥交换名称。这个练习不证明系统已经安全，只帮助建立“协议实际依赖具体算法”的感觉。

### 第二阶段：机器人闭环常识

先理解传感器、坐标、状态估计、规划和控制。可以从 Nav2 的 transform 说明、MoveIt 的概念文档、Modern Robotics 的运动学课程入门。目标是能画出一个机器人任务的数据流，把“模型输入图像输出动作”还原成完整系统。

练习：任选一个场景，例如移动机器人送货，画出下面这张表。

```text
任务: 从 A 点移动到 B 点
传感器: 相机、LiDAR、轮速计、IMU
状态估计: 机器人当前位姿、障碍物位置
规划: 全局路径、局部避障
控制: 速度命令、制动策略
安全监控: 禁入区、最小人距、传感器超时
```

### 第三阶段：安全威胁建模

把系统拆成资产、入口、信任边界和失败后果。具身系统尤其要写清物理后果，例如撞击、夹伤、误停、隐私泄露和任务中断。PQC 迁移要写清长期保密需求和算法依赖。

一个最小风险表可以这样写：

```text
资产: 固件更新包
入口: OTA 下载链路
现有保护: ECDSA 签名 + TLS
量子相关风险: 长期签名可信性和证书体系要迁移
物理相关后果: 被替换固件可能改变速度限制或传感器处理逻辑
优先级: 高，因为设备寿命长且影响执行器行为
```

### 第四阶段：读项目页和课程页

具身智能项目页通常比论文摘要更适合初学者，因为页面上有图、视频、任务演示和失败边界。Open X-Embodiment/RT-X、RT-2、SayCan、Mobile ALOHA、BadRobot 这些页面可以用来观察任务形式、输入输出、机器人平台和安全问题。读的时候先看效果视频，再继续追问：传感器是什么，控制频率是什么，是否有人类接管，失败样例在哪里，评测场景是否覆盖真实部署。

### 第五阶段：再进入论文和标准

读标准时，从 NIST PQC 项目页、FIPS 标准和 NCCoE 迁移项目开始。读论文时，先读综述、课程和项目页，再进入具体方法。这样能避免一开始就陷进符号或模型名称里。

## 常见错误

1. **把具身智能等同于一个大模型。** 大模型可能参与语言理解、视觉理解或策略生成，但传感器、坐标、状态估计、规划、控制和安全监控仍然决定系统能否行动。
2. **把仿真成功等同于真实安全。** 仿真有价值，可以扩大测试覆盖，但真实世界还有摩擦、延迟、遮挡、传感器噪声和人类行为。
3. **把 PQC 等同于量子计算机上的加密。** PQC 算法运行在传统计算机上，目标是抵抗未来量子攻击。
4. **把标准发布等同于迁移完成。** 标准给出算法基础，系统还要做资产盘点、协议支持、证书流程、互操作测试和运行监控。
5. **自己手写真实密码。** 学习可以写 toy 代码理解概念，真实系统应该使用经过审查、维护和合规验证的库与平台能力。
6. **只讨论安全，不写失效后果。** 具身系统必须写清失败会如何影响人、设备和环境；PQC 迁移必须写清数据需要保密多久、设备还要服役多久。

## 可以关注的研究方向

这里列的是方向地图，暂时不展开成完整选题承诺。

### 1. 具身系统的传感器攻击与鲁棒感知

相机、LiDAR、GPS、IMU 和触觉传感器都可能受到噪声、遮挡、欺骗或环境变化影响。研究问题包括：如何构造可复现的传感器失效场景，如何检测输入异常，如何让系统在不确定性升高时降级到安全行为。

### 2. 运行时安全监控和安全案例

具身模型越强，越需要独立的运行时约束。一个研究路线是把策略输出放进 safety monitor、control barrier function、规则约束、急停机制或人类接管流程中，分析哪些安全属性可以在运行时检查。

### 3. 仿真到现实的测试覆盖

Gazebo、MuJoCo、Isaac Sim、Drake 等工具可以生成场景、动力学和控制实验。关键问题是让仿真测试覆盖真实风险，避免只生成好看的 demo。测试指标、场景组合、失败样例和现实校准都很重要。

### 4. 视觉语言动作模型的安全评测

VLA 模型把视觉、语言和动作连起来，研究热度很高。安全评测要追问：危险指令是否被拒绝，歧义任务是否请求确认，场景变化是否触发重新规划，模型是否会把语言诱导凌驾于物理约束之上。

### 5. 机器人和边缘设备的 PQC 迁移

机器人、车辆、传感器网关和工业控制设备生命周期长，算法迁移难度大。研究问题包括：嵌入式设备上 PQC 的性能和包大小，设备身份和固件签名如何迁移，老设备如何保持密码敏捷性，迁移期间如何做混合模式和互操作测试。

### 6. 证据链和事故复盘

具身系统发生事故后，需要日志、模型版本、传感器摘要、命令链路、固件版本和时间戳支持复盘。长期可验证的签名、哈希和时间戳策略会与 PQC 迁移相连。

## 最小练习

这篇文章只提供三个安全的入门练习。

**练习一：画一个具身系统闭环。** 选择“机械臂抓杯子”“移动机器人巡检”“无人机避障”任意一个场景，写出传感器、坐标、状态估计、世界模型、规划、控制、安全监控和日志分别是什么。

**练习二：做一张密码资产草表。** 选择一个熟悉的小系统，例如个人网站、家庭 NAS、实验室设备或本地服务，列出 TLS、SSH、代码签名、备份加密、软件包更新分别使用什么机制。只做观察，不改配置。

**练习三：把两张表合并。** 假设这个系统是一台长期服役的移动机器人，补充：哪些通信要认证，哪些更新要签名，哪些日志要长期可验证，哪些传感器失效会造成物理后果。

一个可接受的练习输出类似：

```text
系统: 仓库移动机器人
传感器: LiDAR + 相机 + IMU + 轮速计
关键动作: 导航、避障、停靠、远程任务下发
密码资产: TLS 设备证书、OTA 固件签名、日志签名、SSH 运维密钥
PQC 关注点: 设备寿命 8 年以上，证书和固件签名需要迁移计划
具身安全关注点: 人车混行、遮挡、急停、低电量返航、传感器时间戳过期
下一步: 画数据流和信任边界，再读 Nav2/MoveIt/NIST PQC 资料
```

## 当前结论

具身智能安全和抗量子密码看起来一个偏机器人，一个偏密码学，但它们都会落到同一个问题：真实系统如何在长生命周期内保持可信、可验证、可更新、可复盘。具身智能提醒我们，安全要面对传感器、控制和物理后果；抗量子密码提醒我们，身份、通信、签名和长期保密不能只按今天的攻击能力设计。

对初学者来说，最稳的路线是先补系统边界：网络和密码的基本用途，机器人闭环的基本层次，风险表的写法，官方标准和课程资料的读法。后面再深入某个研究方向，才不会被单个模型、单个算法或单个演示视频带偏。
